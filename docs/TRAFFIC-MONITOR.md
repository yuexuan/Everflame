# 用户流量监控

`/user/traffic` 沿用当前 Malio/Tabler 主题及账号认证。所有查询强制使用当前登录账号 ID，管理员也不能通过请求参数读取其他账号。

## 时间范围

两个面板共用一个时间选择，查询窗口为 `[开始, 结束)`，使用应用时区（当前 Asia/Shanghai）。

- 近24小时：现在向前滚动24小时，按小时统计。开始和当前小时可能是部分小时，因此最多25个小时桶。
- 今天：当天00:00至现在，按小时统计，不包含未来小时。
- 昨天：昨天00:00至今天00:00，按小时统计，共24小时。
- 近7天、近30天：包含今天，按天统计。
- 近3个月、近半年：包含今天，开始日期按结束日期次日向前3/6个自然月计算，按天统计。
- 自定义：开始、结束日期均包含；当天截至现在，其他结束日期包含到次日00:00。单日按小时，多日按天统计。
- 单次最多6个自然月：结束日期次日不得晚于开始日期加6个月，月份末日按目标月份实际天数截断。未来日期、逆序、无效日期、超长范围均由前后端校验。无效请求返回400并显示提示。

自定义弹层采用 Tabler Datepicker 双月日历，快捷项为今天、昨天、近3个月、近半年。支持手动输入、日历联动、取消和应用；点击应用前不会改变页面已应用的时间范围。Tabler Core 固定1.7.4；Vanilla Calendar Pro 3.4.0（MIT）本地托管，并保留许可证。字体、按钮、日期区间与节点占比条使用现有主题色。

## 数据含义

- 上方概览仍来自账号账面用量，按节点倍率扣费。
- 流量趋势和节点用量由同一批实际上传＋下载字节生成，节点总和与趋势期间总量相等。节点按用量降序排列，占比以期间总传输量为分母，展示百分比可能因四舍五入不等于100%。
- Agent 节点直接读取已存在的 `ef_usage` 事件账本，仅统计 `charged=1` 的正式启用事件，`raw_u+raw_d` 为实际传输，忽略倍率。事件归属规则与 EfSync 一致：`max(started_at, ended_at-1)`，跨边界事件整笔归入该时刻所在小时，不按时长分摊。查询在数据库中按节点和小时聚合，新增 `user_time(user_id, charged, ended_at)` 索引，避免取出半年原始事件到 PHP。
- 普通 WebAPI 节点新增 `node_hourly_usage` 按用户、节点和小时原子累加，沿用 `traffic_log` 开关。普通节点只有小时精度，因此滚动24小时的最早部分小时包含该小时已上报的总量；今天和昨天的整小时边界不受影响。
- 旧 `hourly_usage` 不具备节点归属，不会伪造为节点数据，也不与新账本重复叠加。普通节点新维度从部署后开始采集；已删除节点仍通过标识显示有账本的流量。
- 未采集、未上报或已清理的时段保持空值；实际零值保留为零。页面明确提示历史不完整、无法恢复。Agent 账本未在此功能内清理，普通节点新明细由现有 Cron 至少保留186天，原小时日志的保留配置不变。

## 数据结构与部署

先备份数据库，再执行幂等的增量结构准备（只新增表/索引，不删除旧用量）：

```powershell
docker compose build app
docker compose run --rm --no-deps app php scripts/migrate-node-traffic.php
```

结构准备后再按部署配置重建 app；若启用 Cloudflare/外部数据库，使用原有对应的 Compose 覆盖文件。2026-11-09 已完成增量结构准备、镜像构建及 app 容器替换，上线后通过 HTTPS 已登录页面验收。

```powershell
docker compose -f compose.yaml -f compose.cloudflare.yaml up -d --no-deps app
```

首次部署也需执行结构准备，普通 WebAPI 采集依赖新增表。不要仅用 docker cp 更新运行中的模板。
